# Проверка организационных изменений

Проект HackAlem: сравнение подразделений и функций до/после реорганизации с открываемыми источниками.

**Состояние:** frontend «Контур» подключён к FastAPI; реализованы извлечение документов, агентный цикл, отчёт и источники. Проверки настоящей модели и ограничения описаны в docs/INTEGRATION_RESULTS.md. Сумма промо показана пользователем; остаток, срок и списания проверяются в его биллинге.

**Проверенный результат:** на двух пользовательских DOCX Luna / medium отразила **6/6 заранее выбранных контрольных изменений**. Готовый отчёт опубликован и открыт через интерфейс: 212 функций, 100 сопоставлений, одно замечание возможной потери, 8 минут 21 секунда, оценочно $0.0675. Это ограниченная ручная приёмка одного прогона, не оценка точности на всех документах. 98 backend-тестов и 29 браузерных тестов прошли; production build успешен. Обе дополнительные возможности — сравнение цитат рядом и локальная проверка сотрудником — подключены.

Сборка отчёта теперь разделяет промежуточные заметки между проходами и сохраняет существенные изменённые и неизменённые условия в объяснениях. Предыдущий прогон дал 4/6 полностью + 2 частично. На небольшом авторском комплекте medium прошёл 5/5 сценариев; результаты, источники контрольных проверок и ограничения — [отчёт проверки](docs/INTEGRATION_RESULTS.md).

ТЗ не задаёт процентный порог точности: приёмка проверяет известные изменения и их источники. 5/5 на небольшом авторском примере не означает 100% точность на новых документах. Доля найденных изменений, ошибочные замечания и правильность цитат оцениваются отдельно; прочитанный документ не означает, что извлечена каждая обязанность.

## Запуск

Нужны Git, [uv](https://docs.astral.sh/uv/getting-started/installation/) и собственный OpenAI API key. Проверено на Windows с Python 3.12.11.

```sh
git clone https://github.com/BAITC-Hacks/hack-1086dac4-amazing-guys.git
cd hack-1086dac4-amazing-guys
uv sync --project backend --locked --python 3.12
```

Скопируйте `.env.example` в `.env` в корне проекта и впишите `OPENAI_API_KEY`. Существующий `.env` не перезаписывайте. Сервер читает ключ только из этого файла, игнорируя одноимённую переменную окружения процесса. `.env` исключён из Git; ключ не передаётся браузеру.

Модель — `gpt-6-luna`, настройка `OPENAI_REASONING_EFFORT=medium` (выбранный пользователем режим по умолчанию). Режим `none` остаётся доступен. Точное воспроизведение прежнего алгоритма требует коммита до добавления обзора различий (`b2b162a`); результаты разных версий разделены в отчёте интеграции.

```sh
uv run --project backend --locked uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

В отдельном терминале запустите основной интерфейс:

```sh
cd frontend
npm ci
npm run dev
```

Нужен Node.js 22.12+. Откройте http://127.0.0.1:5173 и выберите режим **«Сервер»**. «Открыть пример» показывает заранее подготовленное демо без AI. Для собранной версии: `npm run build` и `npm run preview`, адрес http://127.0.0.1:4173. Оба адреса разрешены backend по умолчанию.

Технический резервный UI: http://127.0.0.1:8000. Документация backend: `/docs`; схема: `/openapi.json`; проверка конфигурации без запроса к модели: `/api/health`.

Выберите `fixtures/org-review/before.md` в «До», `after.md` в «После», нажмите начало анализа. **Это платные запросы API**, передающие извлечённый текст OpenAI. Проверьте промокредит в аккаунте заранее. `expected.json` — эталон для оценки, его не загружать модели. Комплект авторский, не данные организатора.

## Проверка выводов в интерфейсе

- **«До → После»:** откройте источники строки в «Сравнении», затем «Сравнить цитаты рядом». Точные цитаты показаны в двух колонках с контекстом. При одной цитате с каждой стороны подсвечиваются текстовые различия. При нескольких источниках или слишком длинных цитатах подсветка отключается с пояснением: попарное соответствие не угадывается.
- **Решение сотрудника:** в «Замечаниях» откройте «Проверить основания». Выберите «Подтверждено», «Отклонено» или «Нужно уточнение», добавьте комментарий и нажмите «Сохранить решение». Сводка решений обновляется в списке. Решения сохраняются только в этом браузере для данного анализа; это не общая командная база и не изменение исходного ответа модели. Очистка браузерного хранилища удаляет решения. Доступен сброс; ошибка сохранения показывается явно.

Скачивание отчёта создаёт **JSON исходного ответа модели**. Локальные решения сотрудника в него не входят; PDF-экспорт не реализован. Дополнительных вызовов модели для этих двух возможностей нет.

## Обработка

1. Парсеры читают DOCX, XLSX, текстовый PDF, TXT или MD с адресами абзацев, таблиц, страниц и ячеек.
2. Модель `gpt-6-luna` получает полный извлечённый текст: каждый ID стоит непосредственно рядом со своей цитатой и версией, порядок сохранён. Для одной пары длинных редакций (от 100 фрагментов суммарно) код сначала строит блоки текстовых различий, а модель отдельно разбирает каждый блок: смысловое изменение, сохранение при перефразировании, неопределённость или редакционная правка. Затем модель проверяет гипотезы инструментами `search_functions` и `read_evidence` по полному комплекту и оформляет до двух групп блоков отдельно. Код объединяет отчёты, сохраняя связи функций, замечаний и источников. Для небольших комплектов и нескольких документов на одной стороне используется прежний общий проход. Механическое выравнивание не доказывает смыслового соответствия.
3. При допустимом размере схемы модель выбирает адреса цитат из списка текущих источников. Для функции дополнительно возвращает дословный фрагмент: код сверяет его с цитируемым источником. Сервер наследует источники по явным связям функций; к строкам подразделений добавляет абзац той же версии с дословным полным названием, если модель сослалась только на обязанности/сокращение. Затем проверяет ссылки, версии, соответствия и выполненный поиск перед возможной потерей. Присоединение названия не доказывает правопреемство. При обзоре различий проверяется, что разобраны все блоки. Источники смысловых заметок, не включённые в итоговую матрицу, изменения подразделений или замечания, перечисляются в событии `review_source_coverage`; ограничение охвата добавляется в заключение. Это не число пропущенных смысловых изменений. Эти проверки не доказывают правильность смыслового вывода и не гарантируют обнаружения всех самостоятельных изменений внутри блока.
4. Матрица, замечания, заключение, события инструментов, расход и цитаты сохраняются в `outputs/analyses/`. Исходные бинарные файлы не сохраняются. Браузер открывает точную цитату через API.

Стек: FastAPI/Pydantic, OpenAI SDK, python-docx, openpyxl, pypdf. Версии закреплены в `backend/uv.lock`. Один процесс и локальный пользователь, файловое хранение. Запускать с одним worker. Перезапуск помечает незавершённые задания ошибкой; готовые отчёты доступны по ID. Новый анализ требует повторной загрузки файлов.

## Проверки и ограничения

```sh
uv run --project backend --locked python -m pytest backend/tests -q -p no:cacheprovider
```

Тесты проверяют созданные DOCX/XLSX/PDF, адреса и цитаты, HTTP, повторные запросы, восстановление состояния, ошибки и лимиты агента. Ключ и сеть не нужны. Это не измерение качества модели на случаях ТЗ. HTTP-примеры: `fixtures/api/`.

Лимиты: по 5 файлов каждой версии, 5 МиБ на файл, 250 000 символов исходных цитат (без повторённого соседнего контекста), до 6 запросов модели, до 8 вызовов инструментов, до 600 секунд модельного анализа. Для длинной пары: один запрос обзору, до двух инструментальных раундов, до двух частей отчёта и одна коррекция суммарно. Для простого прохода без обзора — до трёх инструментальных раундов, один отчёт и одна коррекция. Повторный ответ снова проходит проверку; незавершённый или некорректный отчёт не публикуется. Оценочный бюджет анализа $0.25 — локальная проверка по тарифам, не ограничитель счёта OpenAI. Неизвестный расход после сбоя не выдаётся за нулевой. Прежний `Idempotency-Key` с теми же файлами возвращает прежнее задание без нового анализа.

OCR, DOC/XLS, изображения и сложные вложенные структуры полностью не поддерживаются. Непрочитанные части отмечаются предупреждениями. Возможная потеря означает «назначение не найдено в предоставленных документах». Поиск лексический; выводы и полнота реестра функций требуют проверки человеком. Нет авторизации и изоляции пользователей: запуск локальный, не публичный сервер. Предоставлены две обезличенные редакции положения о внутреннем аудите; локальные файлы не включены в репозиторий. Независимый запуск товарищем по общей инструкции ещё предстоит.
