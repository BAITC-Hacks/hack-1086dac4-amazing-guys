# Интерфейс и следующий командный шаг

**Новая задача от пользователя:** параллельно проверить кибербезопасность, доработать графику в принятом стиле «Контур» и самостоятельно прогнать общую версию. Backend-алгоритм сейчас дорабатывается: сборка отчёта по двум группам прошла живую оценку v7 — 6/6 контрольных изменений. HTTP r1 сохранён. Проверить ключи только на сервере, недоверенный текст документов/вывод в браузере, обработку загрузок, ошибки и ограничения доступа с учётом локального однопользовательского прототипа. Изменения backend/контракта выделять отдельно от графики и согласовывать через пользователя/Git, чтобы не затереть текущую работу.

**Отчёт после проверки:** commit, команды запуска, результат реального анализа и открытия цитат, найденные проблемы безопасности, изменённые файлы. Не загружать expected.json модели; не коммитить ключи, реальные документы и outputs. Число прошедших программных тестов не означает точность AI-анализа.


Статус: интерфейс «Контур» объединён с backend по r1. Живые проверки и оставшиеся ограничения — [docs/INTEGRATION_RESULTS.md](docs/INTEGRATION_RESULTS.md). Дизайн принят пользователем: сохранить цвета, шрифты, расположение блоков и панель источников. Новые возможности — после проверки общей версии.

Цель: загрузить документы до/после, увидеть статус анализа, открыть матрицу соответствий и перейти от замечания к точному фрагменту.

Экраны:
1. Две области загрузки «До» и «После», списки файлов, кнопка начала. Не отправлять пустой комплект.
2. Этап обработки и проблемы чтения. Неполный анализ должен быть заметен.
3. Изменения подразделений, матрица функций, фильтр замечаний и заключение.
4. Панель источника: версия, файл, пункт/страница/лист, цитата и контекст.

Приоритет — проверяемость источников. Не начинать со сложной оргсхемы или общего чата. Авторские фикстуры помечать демонстрационными данными, не результатом AI.

Работа ведётся в общей ветке main. Друг владеет frontend/, капитан backend/ и AI/извлечением. Договор API_CONTRACT.md r1. Общие документы и изменения договора координируются с капитаном. Перед push получать изменения команды и объединять их с сохранением работы; не использовать force push. Запуск — README.md. CORS разрешает порты 5173/4173/3000. Localhost на твоём компьютере требует собственного запуска backend и локального .env. Не менять backend/static/demo.html — временный технический интерфейс капитана.

Используй свой существующий навык создания сайтов и папку референсов для дизайна интерфейса. Укажи своей сессии их фактическое расположение. Функции, состояния экранов и обмен с сервером бери из общего задания и API-контракта. Не создавай отдельный независимый продукт; реализуй интерфейс в frontend/ общей ветки main. Если твой навык предлагает другой стек или формат API, сначала сообщи координатору.

Приёмка UI: реальный запрос к backend, обновление статуса, правильная цитата для выбранного замечания, видимые ошибки и partial-coverage. После интеграции — независимый запуск по README.

Ближайшая задача товарища: независимый запуск актуальной main по README. Запустить backend и frontend, выбрать «Сервер», загрузить fixtures/org-review/before.md и after.md, дождаться отчёта и открыть источники замечаний. expected.json не загружать. Проверить также пустую загрузку и ошибку при недоступном backend. Отчёт о результате передать через пользователя/Git: commit, команды, что прошло, точный текст ошибки при сбое. Ключи и пользовательские документы в Git не добавлять. Повторная разработка уже готовых экранов не нужна.


## Две согласованные дополнительные фичи

Пользователь поручил двум субагентам минимум одну, максимум две полезные фичи для Demo Day; основной анализ и финальная проверка имеют приоритет. Дедлайн понимаем как 18:00 сегодня. Печатный отчёт отложен.

1. **Основная: карточка смыслового изменения «До → После»** (ориентир 20–25 минут). По выбранному function_match показать рядом исходные цитаты обеих версий, подсветить текстовые различия и вывести существующий explanation. Получать точные цитаты из evidence API, не генерировать их заново. Сохранить возможность открыть контекст и переключить несколько источников; отсутствие одной стороны честно показать. Подсветка текста — механическое различие, explanation — гипотеза модели. Существующий стиль, мобильная компоновка и безопасный вывод текста обязательны; никаких dangerouslySetInnerHTML для пользовательских документов.
2. **При наличии времени: проверка экспертом** (ориентир 15–20 минут). Для замечаний дать «Подтвердить / Отклонить / Нужна проверка» и необязательный комментарий, счётчик разобранного. Решения локальны в браузере и привязаны к analysis_id; явно обозначить это ограничение. Хранить отдельно от исходного model report и его human_review=unreviewed, не подменять результат API или утверждать серверное/командное сохранение. Не добавлять ключи и исходные документы в localStorage; сохранять только решения/комментарии.

Проверка: реальные источники обеих версий, строки только-after и только-before, ошибка загрузки цитат, мобильный экран, недоверенный текст; для экспертных решений — изоляция разных analysis_id и сохранение после перезагрузки. Перед merge сверить общую main и сообщить commit/результат тестов через пользователя/Git. Минимум 15 минут оставить на общий запуск, README и push.
