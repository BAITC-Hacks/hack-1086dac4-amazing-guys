# Первая задача интерфейса

Статус: backend готов к подключению по r1, полный сценарий моделью ещё не проверен. После получения актуальной main запусти сервер по README. Общие схемы и примеры — fixtures/api/. Первый результат: загрузка → HTTP-статус → источник, затем настоящий модельный отчёт после проверки биллинга.

Цель: загрузить документы до/после, увидеть статус анализа, открыть матрицу соответствий и перейти от замечания к точному фрагменту.

Экраны:
1. Две области загрузки «До» и «После», списки файлов, кнопка начала. Не отправлять пустой комплект.
2. Этап обработки и проблемы чтения. Неполный анализ должен быть заметен.
3. Изменения подразделений, матрица функций, фильтр замечаний и заключение.
4. Панель источника: версия, файл, пункт/страница/лист, цитата и контекст.

Приоритет — проверяемость источников. Не начинать со сложной оргсхемы или общего чата. Авторские фикстуры помечать демонстрационными данными, не результатом AI.

Работа ведётся в общей ветке main. Друг владеет frontend/, капитан backend/ и AI/извлечением. Договор API_CONTRACT.md r1. Общие документы и изменения договора координируются с капитаном. Перед push получать изменения команды и объединять их с сохранением работы; не использовать force push. Запуск — README.md. CORS разрешает порты 5173/3000. Localhost на твоём компьютере требует собственного запуска backend и локального .env. Не менять backend/static/demo.html — временный технический интерфейс капитана.

Используй свой существующий навык создания сайтов и папку референсов для дизайна интерфейса. Укажи своей сессии их фактическое расположение. Функции, состояния экранов и обмен с сервером бери из общего задания и API-контракта. Не создавай отдельный независимый продукт; реализуй интерфейс в frontend/ общей ветки main. Если твой навык предлагает другой стек или формат API, сначала сообщи координатору.

Приёмка UI: реальный запрос к backend, обновление статуса, правильная цитата для выбранного замечания, видимые ошибки и partial-coverage. После интеграции — независимый запуск по README.

Ближайшая задача: две загрузки и опрос статуса по r1, затем матрица и кнопка цитаты. fixtures/api — явно обозначенный режим примеров, не результат AI. Основа: актуальная main с коммитом `feat: add local organizational review backend`. Перед работой git pull --ff-only с сохранением своей работы. Передай через пользователя/Git commit, готовое поведение, результаты проверок, готовность к интеграции и предлагаемые изменения контракта.
