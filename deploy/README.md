# Docker: запуск Kontur

Подробная инструкция к [основному README](../README.md). Нужны Git, Docker Desktop с запущенным
Linux Engine (или Docker Engine + Compose на Linux), интернет для первой сборки и
собственный OpenAI API key для настоящего анализа. Python и Node на компьютере не нужны.

## Первый запуск

```sh
git clone https://github.com/BAITC-Hacks/hack-1086dac4-amazing-guys.git
cd hack-1086dac4-amazing-guys
```

Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Существующий файл не заменяйте.
На Windows PowerShell:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

На macOS/Linux:

```sh
test -f .env || cp .env.example .env
```

Заполните `OPENAI_API_KEY`. Настройки модели уже заданы: `gpt-6-luna`, `medium`.
Ключ не нужен для автоматических тестов, но нужен для анализа файлов.
Деморежим удалён: без ключа можно открыть только интерфейс загрузки.

```sh
docker compose up -d --build --wait
docker compose ps
```

Откройте **http://localhost:8080**. В `ps` оба сервиса должны иметь состояние `healthy`.
Это проверка приложения, не платный запрос и не проверка доступности API модели.

В интерфейсе загрузки для короткой проверки:

- «До»: `fixtures/quick-check/before.docx`.
- «После»: `fixtures/quick-check/after.docx`.
- Нажмите «Сравнить документы»; ожидается одно замечание возможного дублирования
  ведения реестра двумя отделами. Входные файлы авторские и содержат одну добавленную
  обязанность. README с ожиданием модели не загружать.
- «Сравнение» → источники строки → «Сравнить цитаты рядом».
- «Замечания» → «Проверить основания» → решение и комментарий → «Сохранить решение».

Анализ платный и отправляет извлечённый текст OpenAI. Доступ к аккаунту и кредит
не входят в репозиторий. Автоматические тесты подменяют модель; интерфейс продукта
показывает только реальные серверные отчёты.

## Проверки и управление

```sh
# 102 автоматические backend-проверки; API-ключ и платные вызовы не используются.
docker compose --profile checks run --build --rm backend-tests

# Проверить API через тот же адрес, что использует браузер.
curl http://localhost:8080/api/health

# Посмотреть диагностический журнал.
docker compose logs --tail 100 backend web

# Остановить контейнеры, сохранив отчёты.
docker compose down

# Запустить снова; существующие отчёты останутся в Docker-томе.
docker compose up -d --wait
```

После изменения кода или ключа повторите `docker compose up -d --build --force-recreate --wait`.
Не перезапускайте backend во время нужного анализа: незавершённое задание будет
помечено прерванным. Общий предел обработки — 15 минут, интерфейс ожидает до 16 минут;
число модельных запросов и оценочный бюджет остаются ограничены.

Если 8080 занят, задайте `KONTUR_PORT=8081` в корневом `.env` и повторите запуск.
Тогда адрес будет http://localhost:8081. Frontend использует тот же origin, менять
его сборочную переменную или CORS для этого не требуется.

При ошибке подключения Docker проверьте, что Docker Desktop запущен и выбран Linux
Engine. При `model_configured: false` проверьте `OPENAI_API_KEY` в корневом `.env` и
пересоздайте backend. При `model_unavailable` проверьте журнал: работающий контейнер
не гарантирует доступность внешнего сервиса модели. Не отправляйте ключи в отчётах
об ошибках.

## Что зафиксировано и где хранятся данные

- Базовые Python, Node и Nginx образы закреплены SHA256 digest; uv — версией 0.9.28.
  Python-зависимости устанавливаются через `uv sync --locked`, frontend — `npm ci`.
- Frontend собирается отдельным этапом. Финальный веб-образ содержит только сборку
  и конфигурацию Nginx; API доступен через `/api/`, backend-порт на хост не публикуется.
- Единственный опубликованный порт привязан к `127.0.0.1`. Это локальный прототип
  без пользовательской авторизации; гостевой вход — UI-режим, не защита API.
- Оба сервиса работают без root; привилегии ограничены. Файловая система backend
  доступна только для чтения, кроме временной папки и тома результатов.
- `.env` подключается только при запуске и только для чтения. `.dockerignore`
  исключает ключи, локальные документы, результаты, `.venv` и `node_modules` из сборки.
- Отчёты и извлечённые цитаты: Docker-том `kontur_analysis-data`, путь `/data/analyses`.
  Исходные бинарные загрузки backend не сохраняет. `docker compose down` оставляет
  том; добавление `--volumes` удаляет данные. Нативные `outputs/analyses` сюда не копируются.
- Решения сотрудника хранятся в браузере для текущего origin. Решения с порта 4173
  автоматически не появятся на 8080; серверный JSON-отчёт их не содержит.

Это упаковка проверяемого прототипа, не гарантия качества каждого ответа модели.
Содержательные результаты и известные ограничения — [журнал интеграции](../docs/INTEGRATION_RESULTS.md). Проверки упаковки — [журнал Docker](../docs/DOCKER_VERIFICATION.md).
