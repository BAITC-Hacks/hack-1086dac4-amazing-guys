## Что нужно исправить

### 1. Доступ к API и запуск с постороннего Origin

Места: [backend/app.py](../backend/app.py), `create_analysis`, `analysis_report`, `get_evidence`, настройка CORS.

Маршруты не требуют авторизации. Проверка с `Origin: https://untrusted.example` без
`Idempotency-Key` и без авторизации получила **202** и запустила тестовый анализ.
Чтение отчёта по известному ID без авторизации получило **200**.
Заголовка `Access-Control-Allow-Origin` в постороннем ответе нет: браузеру запрещено читать ответ,
но серверная операция всё равно выполнена. Дополнительные ограничения конкретного браузера
на доступ к локальной сети в этом тесте не оценивались.

Для публичного адреса это риск доступа к документам по известному ID и несанкционированного
расхода модели. UUID затрудняет угадывание, но не заменяет проверку доступа.
Лимит очереди в два задания не ограничивает число последовательных запусков.

Исправление: аутентификация, проверка доступа к анализу, ограничение частоты/общего бюджета.
Для локального прототипа также отклонять недопустимый Origin до обработки тела и требовать
секретный токен доступа, который не встроен в VITE-сборку. CORS не считать авторизацией.
До этого сохранять запуск на 127.0.0.1, без публичного туннеля.

### 2. Ограничение загрузки применяется слишком поздно

Место: [backend/app.py](../backend/app.py), параметры `UploadFile` и проверка размера в `create_analysis`.

Лимиты 5 файлов на сторону / 5 МиБ на файл проверяются в обработчике после multipart-разбора.
Проверенный код установленного Starlette ограничивает `max_part_size` для обычных полей,
а файловые части записывает отдельно; это не ранний предел размера файла или запроса.
Большая загрузка может занять ресурсы до ответа 413. Нагрузочная атака не проводилась.

Исправление: ограничить суммарное тело запроса до multipart-разбора (proxy/ASGI),
включая потоковые запросы без Content-Length; ограничить число частей и время загрузки.
Сохранить текущую пофайловую проверку как дополнительную защиту.

### 3. Извлечение файлов не охвачено таймаутом модели

Место: [backend/app.py](../backend/app.py), `process`: `asyncio.to_thread(extract_document, ...)`
выполняется внутри общей блокировки, а `wait_for` установлен только вокруг `run_agent`.

Контрольная проверка с искусственной задержкой парсера и таймаутом 0,01 с завершилась
за 0,077 с со статусом completed. Это подтверждает границу таймаута; вредоносный PDF не использовался.
Зависший парсер может удерживать очередь даже после прекращения ожидания на frontend.
Ограничения ZIP, страниц и числа фрагментов полезны, но не ограничивают любое потребление CPU/RAM.

Исправление: выделить парсинг в изолированный процесс с ограничением времени/памяти и
возможностью завершения. Один `wait_for` вокруг потока не останавливает выполняющийся парсер.
Учесть время очереди/извлечения в общем сроке операции и согласовать его с ожиданием клиента.

### 4. Название PDF не соответствует фактическому экспорту

Место: [frontend/src/App.tsx](../frontend/src/App.tsx), `exportReport` и две кнопки экспорта.
«Скачать отчёт PDF» сохраняет JSON. Это функциональный дефект, не уязвимость безопасности.
Исправление: настоящий PDF-экспорт либо точная подпись JSON.

## Уже действующие защиты

- Схемы входов/выходов и безопасные сообщения об ошибках; фронтенд отклоняет неверный формат ответа.
- Текст источников выводится как текст, без исполнения HTML; соответствующая браузерная проверка проходит.
- ID анализа проверяется по строгому формату; источник разрешается только внутри выбранного анализа.
- Проверки расширений, размеров, пустых файлов, распакованного Office-объёма и явных XML entity/DOCTYPE-маркеров.
- Повтор с прежним Idempotency-Key не создаёт второй анализ; очередь и вызовы модели ограничены.
- Инструменты агента ограничены поиском и чтением источников текущего комплекта; произвольные инструменты отклоняются.
- Ключ модели остаётся на сервере; локальные `.env`, загрузки и результаты исключены из Git.

## Границы проверки

Не проверены: живой AI на последнем коммите, семантическая устойчивость к prompt injection,
все CVE Python-зависимостей, тяжёлая нагрузка, публичный TLS/proxy, многопользовательские сценарии
и полный анализ истории Git. Статические меры против prompt injection не доказывают его невозможность.
Для локальной демонстрации механическая интеграция работает; публичную эксплуатацию без исправлений 1–3 не рекомендую.
