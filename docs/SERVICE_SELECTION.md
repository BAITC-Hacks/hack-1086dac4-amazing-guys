# Выбор компонентов и бюджет

Дата проверки источников: 2026-09-23. Пользователь сообщил о $50 OpenAI API и $50 NVIDIA. Балансы, срок действия, список доступных моделей и назначение NVIDIA-кредита не проверены. Платные вызовы и серверы не запускались.

## Решение для первого эксперимента

Использовать локальный Python backend, прямые открытые библиотеки чтения документов и OpenAI API для семантики. Не поднимать отдельный GPU-сервис, векторную БД или платформу RAG без обнаруженной необходимости. Внешний GPU может быть полезен для распознавания сложных/сканированных документов, но его необходимость пока не установлена.

| Компонент | Применение | Затраты и решение |
| --- | --- | --- |
| python-docx | DOCX: абзацы и таблицы с адресами | Локально, CPU, без API-расхода; первый кандидат |
| openpyxl | XLSX: листы и ячейки | Локально, CPU, без API-расхода; первый кандидат |
| pypdf | Текстовый PDF по страницам | Локально, CPU, не OCR; первый кандидат |
| Docling | Сложные PDF, таблицы, OCR, структурированный JSON | Сравнить на проблемных файлах; CPU допустим, GPU не обязателен |
| MarkItDown | Быстро ознакомиться с содержимым | Уже доступен; Markdown сам по себе не сохраняет все нужные адреса |
| OpenAI Responses API | Извлечение функций, сопоставление и инструменты агента | Плата за токены, без аренды GPU; основной модельный путь |
| NVIDIA hosted NIM | Альтернативная модель/специализированный endpoint | Только после проверки доступа, качества русского текста и стоимости/лимитов |
| Brev GPU VM | Отдельное размещение сервиса обработки | Имеет смысл лишь при подтверждённых GPU-кредитах и измеренной необходимости |

Это рекомендации на основании документации, не результаты бенчмарка. Прямые библиотеки не покрывают старые .doc/.xls и произвольные сканы; формат реального пакета ещё неизвестен. Не отказываться от обязательного формата ТЗ молча: при его наличии добавить нужный путь и проверить его.

## Почему адресация важнее простого Markdown

Нужен единый фрагмент с file_id, version, locator, quote и контекстом. Для Word сохраняем пункт/абзац/таблицу; для Excel лист и ячейки; для PDF страницу и фрагмент. Прямые парсеры позволяют сформировать эти адреса без модельного вызова. Если используется Docling, сохранять структурированный DoclingDocument/JSON и доступную provenance, а не только Markdown. Полноту provenance для каждого формата проверять отдельно.

Первый опыт: DOCX с пунктами/таблицей, XLSX и PDF с текстовым слоем; 10 заранее выбранных цитат должны совпасть с правильными адресами 10/10. Проверить границы таблиц и время первого/повторного запуска. При проблемах PDF сравнить Docling CPU на тех же страницах. Данные организатора пока отсутствуют; авторский пример только проверяет механику.

## Модель: выбор через малую проверку

По официальной документации кандидаты:

| Модель | Цена Standard за 1M входных/выходных токенов, короткий контекст | Роль в проверке |
| --- | --- | --- |
| gpt-6-luna | $0.10 / $0.50 | Первый дешёвый кандидат для структурированного извлечения и сопоставления |
| gpt-6-sol | $2.00 / $10.00 | Кандидат для сложного агентного анализа, сравнение на проваленных дешёвой моделью случаях |

Обе карточки документируют function calling и structured outputs; рекомендуемый путь для инструментов — Responses API. Поддержка API в документации не доказывает доступ с ключом команды. Модель разработки Codex и модель приложения — разные настройки.

Сначала 5 существующих размеченных случаев. Модель не видит expected.json. Проверяем реальные связи функций, потери/дубли, отрицательные примеры, цитаты, ошибки структуры, время и токены. Дешёвую модель не принимать при систематических пропусках; более сильную проверять на этих же ошибках. Первой версии достаточно одного выбранного модельного пути, без сложной маршрутизации провайдеров.

Пример оценки, не измерение: суммарно 40 000 обычных входных и 8 000 оплачиваемых выходных токенов по всем вызовам анализа стоят около $0.008 на Luna либо $0.16 на Sol по указанным ставкам. Это не прогноз размера настоящего анализа. Повторная пересылка текста, reasoning, дополнительные вызовы, изображения и инструменты могут увеличить счёт; длинный контекст и специальные режимы имеют другие ставки. Фактический расход брать из usage и текущего тарифа.

## Бюджетная политика предложения

- $5 — максимум начальной серии измерений OpenAI; это предел, не цель расхода.
- $15 — резерв финальных проверок и демонстрации.
- $30 — доступно для дальнейшей разработки после измерения стоимости успешного анализа.
- NVIDIA $50 пока не распределять: требуется название сервиса/условий. Это отдельный баланс, не общий переносимый бюджет $100.
- Извлечённый текст и стабильные метаданные хранить один раз. UI разрабатывать на размеченных фикстурах, но итоговую агентную проверку проводить с реальной моделью.
- При реализации поставить лимиты шагов, повторов, токенов и расходов. Пока они не написаны — не заявлять технически гарантированный cap.

## Что означает NVIDIA-доступ

NVIDIA NIM API Catalog позволяет вызывать модели на инфраструктуре NVIDIA. Такой API-доступ не даёт сам по себе право загрузить произвольный сервер или Docker-контейнер в тот же сервис.

Brev предоставляет GPU-виртуальные машины, где можно разворачивать свои сервисы; работающие машины оплачиваются по времени. Поэтому применимость кредита зависит от того, где он выдан. Бесплатный/открытый код не означает бесплатные GPU, хранение и поддержание сервиса.

На локальном компьютере проверено: Windows, Python 3.11.8, NVIDIA RTX 4050 Laptop 6141 MiB VRAM, около 16 GB RAM. Docker CLI установлен, но сервер Docker в момент проверки не запущен. Это не блокирует прямое чтение CPU-библиотеками. Производительность Docling здесь не измерялась.

NVIDIA NeMo Retriever также рассмотрен как система извлечения. Его поддержку оборудования/режима и установки надо выбирать по конкретному профилю; полный GPU-stack не нужен для первой проверки малых текстовых комплектов. Не устанавливать его только ради расходования кредита.
