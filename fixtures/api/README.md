# HTTP-примеры контракта r1

Эта папка содержит **авторские HTTP-фикстуры для разработки и тестирования**. Они создаются через настоящее FastAPI-приложение с подменённой функцией агента. Парсер, маршруты, схемы и сериализация работают; OpenAI не вызывается. Это не эталон качества AI и не набор приватных результатов.

Общее устройство: [README проекта](../../README.md). Маршруты/модели: [API_CONTRACT.md](../../API_CONTRACT.md), [backend/models.py](../../backend/models.py), [backend/app.py](../../backend/app.py). Использование в UI: [frontend/README.md](../../frontend/README.md).

## Состав

| Файл                                         | Где применяется                  | Что содержит                                                                                   |
| -------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------- |
| [openapi.json](openapi.json)                 | Согласование frontend/backend    | Снимок `app.openapi()`: пять маршрутов API, схемы входа/выхода и ошибок                        |
| [accepted.json](accepted.json)               | Ответ POST, HTTP 202             | `analysis_id`, `contract_version=r1`, начальное состояние                                      |
| [completed.json](completed.json)             | GET статуса                      | Завершение, этап, документы, предупреждения, `error=null`, `usage`                             |
| [failed.json](failed.json)                   | GET статуса после фоновой ошибки | `status=failed`, ошибка таймаута и признак повторяемости                                       |
| [report.json](report.json)                   | GET отчёта                       | Минимальный связный пример двух функций, неопределённого сопоставления, замечания и заключения |
| [report-partial.json](report-partial.json)   | Неполное покрытие                | Производная отчёта с частичным чтением и предупреждением                                       |
| [evidence-before.json](evidence-before.json) | Открытие источника «до»          | Точная цитата `before.txt`, её версия, ID и адрес                                              |
| [evidence-after.json](evidence-after.json)   | Открытие источника «после»       | Точная цитата `after.txt`, её версия, ID и адрес                                               |
| [invalid-input.json](invalid-input.json)     | Ошибка ввода HTTP 422            | Конверт `{error:{code,message,retryable}}`                                                     |

ID анализа заменён генератором на **32 нуля**, чтобы diff был стабильным. Этот ID не существует в обычном запущенном backend. Нельзя просто обращаться к реальному серверу с ID из фикстуры и ожидать получить её содержимое. Источники `doc-001:e00001` и `doc-002:e00001` относятся к этому вымышленному ответу; совпадение имён ID между двумя настоящими анализами не делает их общими источниками.

`usage.model=fixture-not-ai`, вызовы и токены равны нулю. Эти значения специально обозначают подмену, а не «бесплатный AI-анализ».

## Чем отличается от других данных проекта

| Папка/файл                                                       | Для чего                                                    |
| ---------------------------------------------------------------- | ----------------------------------------------------------- |
| Эта папка                                                        | HTTP-форматы и контролируемые ответы браузерных тестов      |
| [fixtures/org-review](../org-review/README.md)                   | Входные документы и отдельный эталон пяти смысловых случаев |
| [frontend/src/demo-data.json](../../frontend/src/demo-data.json) | Полный подготовленный демонстрационный отчёт интерфейса     |
| `outputs/analyses/`                                              | Реальные локальные результаты; не коммитятся                |

`report-partial.json` иллюстрирует форму ответа, но не доказывает, что модель корректно обработала конкретный неполный документ. `failed.json` показывает фоновый `failed`; это не HTTP 500. GET статуса при такой ошибке возвращает 200 с полем `error`. Ошибка самого запроса, например `invalid-input.json`, использует HTTP 422 и внешний конверт `error`.

## Как обновить примеры

Команды выполнять **из корня репозитория** после установки backend по его [README](../../backend/README.md):

```sh
uv run --project backend --locked python -m backend.export_contract
```

Генератор [backend/export_contract.py](../../backend/export_contract.py):

1. Создаёт временный каталог и приложение с тестовой конфигурацией.
2. Подменяет `backend.app.run_agent` функцией `example_agent`.
3. Отправляет `before.txt` / `after.txt` через TestClient.
4. Получает статусы, отчёт, источники, ошибку ввода и OpenAPI настоящими маршрутами.
5. Стабилизирует ID и записывает JSON; частичный отчёт/ошибка созданы как явно заданные варианты.

Команда перезаписывает JSON в этой папке, но не README. Проверьте изменения перед коммитом:

```sh
git diff -- fixtures/api
uv run --project backend --locked python -m pytest backend/tests/test_contract.py backend/tests/test_http_contract.py -q -p no:cacheprovider
```

`test_contract.py` проверяет соответствие примеров Pydantic-моделям и связи источников. `test_http_contract.py` сравнивает сохранённую OpenAPI-схему с приложением и проверяет HTTP-ошибки. Обновление только JSON без Python-моделей или только Zod без фикстур оставляет стороны несогласованными.

## Как использовать в frontend

В [frontend/tests/frontend.spec.ts](../../frontend/tests/frontend.spec.ts) запросы перехватываются Playwright: POST получает `accepted.json`, опрос — статус, `/report` — отчёт, `/evidence/...` — источник. В отдельных сценариях маршрут изменяется, задерживается или обрывается. Фикстуры также используются тестами загрузки и карточки сравнения цитат.

```sh
cd frontend
PLAYWRIGHT_CHANNEL=chrome npm test -- --grep 'HTTP r1 adapter|malformed server response|network retry'
```

Для стандартного Chromium после `npx playwright install chromium` можно выполнить ту же команду без `PLAYWRIGHT_CHANNEL=chrome`. Реальный backend и его ключ не нужны. Браузер проверяет ответы Zod-схемами из [contracts.ts](../../frontend/src/contracts.ts); неправильный формат должен дать ошибку, а не успешный экран.

## Правила поддержки

При изменении r1 одновременно сверяйте `backend/models.py`, маршруты, [API_CONTRACT.md](../../API_CONTRACT.md), `frontend/src/contracts.ts`, этот набор и обе стороны тестов. Не редактируйте примеры ради сокрытия несовместимости и не копируйте сюда реальные пользовательские данные. Семантические изменения модели проверяются отдельно на документах; согласованный HTTP-ответ сам по себе не подтверждает смысловую правильность.
